## 一句话总结

> Pi05 通过异质数据共训和高层子任务预测，让 VLA 在未见真实家庭中执行长程移动操作。

---

## 核心贡献

1. **面向开放家庭环境的 VLA 训练 recipe**: 在 [[Vision-Language-Action Model]] 上引入 [[Co-training|异质数据共训]]，把目标移动操作、跨机器人数据、高层语义标注、语言监督和 Web 多模态数据统一训练。
2. **统一高层/低层推理架构**: 同一个模型先预测 [[Semantic Subtask Prediction|语义子任务]]，再基于子任务生成低层 [[Action Chunking|动作块]]，接近 embodied chain-of-thought，但不依赖外部 planner。
3. **离散预训练 + 连续后训练**: 先用 [[FAST+|FAST action token]] 做离散动作预训练，再在 post-training 加入 [[Flow Matching]] action expert 输出连续动作，兼顾训练稳定性和实时控制。
4. **真实未见家庭验证**: 在训练集中未出现的真实厨房和卧室中展示 2-15 分钟多阶段任务，如收拾厨房、整理卧室、放衣服进篮子、把餐具放入水槽。

---

## 问题背景

### 要解决的问题

现有 [[Vision-Language-Action Model]] 往往在与训练分布接近的环境中评估，任务也偏短、偏桌面、偏单技能。Pi05 要解决的是 [[Open-World Generalization|开放世界泛化]]：机器人需要进入没见过的真实家庭，面对新布局、新背景、新物体和长程任务，还能根据简单语言命令完成移动操作。

### 现有方法的局限

- 只扩大目标机器人数据很难覆盖所有厨房、卧室、物体和任务组合。
- 端到端 VLA 的语言跟随能力强，但对长程任务的阶段分解、场景语义和操作迁移仍不足。
- 传统高层 planner + 低层 policy 往往需要两个模型或额外接口，容易产生语义和执行分布错配。
- 纯连续动作 VLA 训练成本高；纯离散动作 token 推理时自回归解码又不适合实时控制。

### 本文的动机

作者认为机器人泛化需要像人一样利用多种经验来源：直接操作经验、其他机器人/其他环境数据、语言指导、Web 视觉语义知识和高层任务分解。[[Vision-Language-Action Model]] 的 token 序列建模能力刚好可以把这些异质监督放在同一个框架中训练。

## 方法详解

### 模型架构

Pi05 是一个层级式 [[Vision-Language-Action Model]]：

- **输入**: 多相机图像 $I_t^{1:n}$、机器人本体状态 $q_t$、用户高层指令 $\ell$。
- **Backbone**: [[PaliGemma]] 风格 VLM backbone，附加较小的 [[Flow Matching]] action expert。
- **核心模块**: [[Semantic Subtask Prediction|高层子任务预测]] $p_\theta(\hat{\ell}\mid o_t,\ell)$ 和低层动作预测 $p_\theta(a_{t:t+H}\mid o_t,\hat{\ell})$。
- **动作表示**: pre-training 中使用 [[FAST+|FAST action token]]；post-training 中加入连续 [[Action Chunking|动作块]] flow matching。
- **输出**: 文本子任务 $\hat{\ell}$，例如 "pick up the plate"；以及动作 horizon 为 50 的连续 action chunk。
- **参数量**: VLM backbone 约 2B；action expert 约 300M。

### 核心模块

#### 模块1: 高层语义子任务预测

**设计动机**: 对于 "clean the kitchen" 这类命令，直接输出动作太难。Pi05 先生成可执行的短语义目标，使长程任务变成一系列局部操作。

**具体实现**:

- 对 MM、ME、CE 中含多个子任务的机器人数据人工标注语义子任务。
- 训练模型在当前观测和高层命令下预测下一步子任务。
- 同时标注相关 bounding boxes，使模型在子任务预测前学习定位当前场景里的关键物体。
- 推理时，模型低频预测子任务，高频基于该子任务输出连续动作。

#### 模块2: 异质数据共训

**设计动机**: 真实家庭覆盖太广，单靠目标 [[Mobile Manipulator]] 数据无法穷举。作者用 [[Co-training]] 从不同数据源转移不同能力。

**具体实现**:

- `MM`: 约 400 小时目标移动操作数据，来自约 100 个家庭环境。
- `ME`: 非移动机械臂在多家庭环境中的数据，用于提供更多真实家庭物体和布局。
- `CE`: 实验室跨 [[Cross-Embodiment]] 数据和 [[Open X-Embodiment]]，提供更广任务和 embodiment 覆盖。
- `HL`: 高层子任务与 bounding box 预测数据，提供长程分解能力。
- `WD`: Web captioning、VQA、object localization 数据，提供物体和场景语义。
- `VI`: [[Verbal Instruction Demonstrations|语言指导示教]]，由人类专家实时用子任务语言驱动已训练低层策略。

#### 模块3: 离散动作预训练与连续动作后训练

**设计动机**: [[FAST+|FAST action token]] 适合高效自回归预训练，但实时控制更需要连续动作分布。Pi05 先离散预训练，再加入 [[Flow Matching]] action expert。

**具体实现**:

- Pre-training: 280k gradient steps，所有任务用 next-token prediction 训练，包括文本、目标框和 FAST 动作 token。
- Post-training: 80k steps，同时保留 next-token prediction 和 action expert 的 flow matching loss。
- Post-training 数据过滤为成功且长度低于阈值的 MM/ME 轨迹，并继续混入 WD 与 HL 以保持视觉语义能力。

## 关键公式

### 公式1: [[Hierarchical VLA|层级 VLA 分解]]

$$
\pi_\theta(a_{t:t+H}, \hat{\ell}\mid o_t,\ell)
=
\pi_\theta(a_{t:t+H}\mid o_t,\hat{\ell})\pi_\theta(\hat{\ell}\mid o_t,\ell)
$$

**含义**: 模型先根据观测和高层命令产生语义子任务，再基于该子任务生成低层动作。

**符号说明**:

- $o_t=[I_t^1,\dots,I_t^n,q_t]$: 当前观测，包括多相机图像和本体状态。
- $\ell$: 用户给出的整体任务命令。
- $\hat{\ell}$: 模型生成的高层语义子任务。
- $a_{t:t+H}$: 从 $t$ 到 $t+H$ 的动作块。

### 公式2: [[Vision-Language-Action Model|多模态 Transformer 输出]]

$$
y_{1:N}=f(x_{1:N}, A(x_{1:N}), \rho(x_{1:N}))
$$

**含义**: Transformer 以 token 类型 $\rho$ 和注意力掩码 $A$ 处理图像、文本、本体状态、离散动作 token 与连续动作 token。

**符号说明**:

- $x_{1:N}$: 输入 token 序列。
- $A(x_{1:N})$: token 间可见性的 attention mask。
- $\rho(x_{1:N})$: token 类型函数，用于决定编码器或 expert 权重。
- $y_{1:N}$: 输出 token，包括文本 logits 和 action expert 输出。

### 公式3: [[Flow Matching|带噪动作路径]]

$$
a^{\tau,\omega}_{t:t+H}
=
\tau a_{t:t+H} + (1-\tau)\omega,\quad
\omega\sim\mathcal{N}(0,I)
$$

**含义**: 在真实动作块和高斯噪声之间插值得到 flow matching 训练输入。

**符号说明**:

- $\tau\in[0,1]$: flow matching 时间步。
- $\omega$: 标准高斯噪声。
- $a^{\tau,\omega}_{t:t+H}$: 带噪动作块。

### 公式4: [[Flow Matching|混合动作训练目标]]

$$
\mathbb{E}_{D,\tau,\omega}
\left[
H(x_{1:M}, f^\ell_\theta(o_t,\ell))
+ \alpha
\left\|
\omega-a_{t:t+H}
- f^a_\theta(a^{\tau,\omega}_{t:t+H},o_t,\ell)
\right\|^2
\right]
$$

**含义**: 总损失同时包含文本/FAST token 的交叉熵，以及 action expert 的 flow matching 向量场回归。

**符号说明**:

- $H(\cdot)$: [[Cross-Entropy Loss|交叉熵损失]]，用于文本和 FAST 动作 token。
- $f^\ell_\theta$: 文本 token 输出头。
- $f^a_\theta$: action expert 输出头。
- $\alpha$: 两种损失的权重；post-training 中使用 $\alpha=10.0$。

### 公式5: [[Flow Matching|低时间步采样]]

$$
p(\tau)=\mathrm{Beta}\left(\frac{s-\tau}{s};\alpha=1.5,\beta=1\right),\quad s=0.999
$$

**含义**: 与 π0 类似，训练时更强调低 timestep 区域，以适应少步 denoising 的实时动作生成。

**符号说明**:

- $s$: 截断阈值。
- $\alpha,\beta$: Beta 分布参数。
- $\tau$: flow matching 时间步。

## 实验

### 数据集

| 数据源 | 规模 | 特点 | 用途 |
|--------|------|------|------|
| MM | 约 400 小时，约 100 个家庭环境 | 目标双臂移动操作平台，家庭清洁/整理任务 | 直接学习目标任务 |
| ME | 多家庭环境非移动机器人数据 | 单臂/双臂，易搬运，环境覆盖更广 | 跨环境和物体泛化 |
| CE | 实验室跨 embodiment 数据 + OXE | 多机器人、多任务，部分任务与评估相关 | 跨任务和跨 embodiment 迁移 |
| HL | 人工语义子任务和 bounding box 标注 | 将长程命令拆成短子任务 | 高层推理与场景 grounding |
| WD | CapsFusion、COCO、Cambrian-7M、PixMo、VQAv2、object localization | Web 视觉语言和室内物体定位数据 | 语义理解和 OOD object 泛化 |
| VI | 语言指导示教 | 人类专家用语言 step-by-step 驱动低层策略 | 高层策略对齐 |

### 实现细节

- **Backbone**: [[PaliGemma]] VLM，2B backbone；action expert 约 300M。
- **动作 horizon**: $H=49$，即 50 步 action chunk。
- **Pre-training**: 280k gradient steps，离散 token 训练，$\alpha=0$。
- **Post-training**: 80k gradient steps，混合 next-token prediction 和 flow matching，$\alpha=10.0$。
- **推理**: 文本子任务自回归采样，动作使用 10 步 denoising。
- **动作归一化**: 每个数据集每个动作维度用 1% 和 99% quantile 归一化到 $[-1,1]$。
- **异构 action space**: 使用固定最大动作维度，低维机器人动作 zero-pad。
- **图像增强**: random crop、resize、rotation、color jitter。

### 主要实验结论

- **真实家庭泛化**: Pi05 在 3 个未见真实家庭中能完成厨房和卧室任务，许多任务持续 2-5 分钟，展示任务长度和环境新颖性上的提升。
- **训练地点 scaling**: 更多训练地点带来更好 end-to-end 表现和语言跟随能力，说明环境多样性比单纯样本数量更关键。
- **共训消融**: ME 和 CE 对操作泛化很关键；WD 对 OOD 物体语言跟随和高层推理关键。
- **模型对比**: Pi05 优于 π0 和 π0-FAST+Flow，说明收益来自共训任务和层级推理，而不仅是 action representation。
- **高层推理**: 显式高层推理最好，但 implicit HL 也强，说明在训练中学习子任务分解本身已经给策略提供了重要结构偏置。

## 批判性思考

### 优点

1. **问题设定更接近真实机器人落地**: 未见真实家庭、长程移动操作、多物体任务，比常见桌面短任务更有说服力。
2. **训练配方解释清楚**: MM/ME/CE/HL/WD/VI 的作用被系统消融，尤其区分了跨机器人数据、Web 语义数据和语言指导的贡献。
3. **统一高层与低层模型**: 避免外接 planner 的接口错配，也让高层子任务数据可以同时影响低层策略表示。
4. **离散与连续动作结合务实**: 用 FAST token 提升预训练效率，用 flow matching 保持实时连续控制能力。

### 局限性

1. **复现难度高**: 关键机器人数据、真实家庭环境、硬件系统和训练基础设施都不可直接复现。
2. **数值结果主要来自图**: 正文趋势清晰，但许多精确数值没有以表格形式给出。
3. **任务语言仍简单**: 模型处理的是相对简单的高层 prompt，还没有复杂偏好、约束、多房间记忆。
4. **物理世界失败仍明显**: 陌生抽屉把手、被机械臂遮挡的污渍、反复开关抽屉等问题说明策略仍缺少稳健状态估计和记忆。
5. **human HL baseline 解释需要谨慎**: 完整 Pi05 超过 human HL oracle，可能说明人给的高层标签和低层策略分布并不完全匹配，而不一定说明模型高层语义更强。

### 潜在改进方向

1. 引入长期记忆和显式状态估计，支持跨房间任务、物体位置记忆和遮挡恢复。
2. 用更丰富的偏好/约束标注扩展复杂语言指令，例如“不要碰易碎物”“先收拾桌面再擦水渍”。
3. 结合失败检测和恢复策略，减少高层子任务循环和低层物理卡住。
4. 将 VI 数据扩展为交互式纠错数据，连接 [[Situated Correction]] 或 online adaptation。

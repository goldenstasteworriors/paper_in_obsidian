# Agent Harness

## 直觉与定义

语言模型决定下一步说什么或调用什么，harness 则规定这些决定如何实际运行。它通常包括工具接口、执行循环、上下文整理、持久记忆、错误恢复、终止和验证代码。

同一个模型放进不同框架，最终成功率和成本可能明显不同；所以智能体能力应理解为模型与运行系统的共同结果。

## 用途

组织长任务、调用工具、保存证据、恢复失败并核验交付结果。研究中应固定执行框架比较模型，或固定模型比较框架；若两者同时改变，需要分解贡献。

## 与易混概念的区别

- Prompt 是框架的一部分，不能代表全部可执行控制逻辑。
- Skill 主要提供可按需加载的操作知识与资源，通常可以在不改框架、不改权重时接入。
- 参数训练改变模型，框架优化改变模型外围的程序，两者也可能交替进行。
- 完成一个开发任务不等于生成的框架能在未见任务和其他执行模型上泛化。

## 代表研究

- [HarnessDev](https://arxiv.org/html/2609.01437)：分创建、进化与隐藏测试，评估框架本身的能力。
- [WHALE](https://arxiv.org/html/2609.00196)：交替优化权重和可执行框架，研究二者互为瓶颈。
- [Repo-To-Skill](https://arxiv.org/html/2609.02749)：固定模型与框架，研究补充操作知识的效果；技能构建成本需独立核算。
- [ASPIRE](https://arxiv.org/html/2608.31111)：只给模糊能力目标，检验框架或权重变化能否改善外部隐藏任务。
